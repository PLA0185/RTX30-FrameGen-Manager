# 安全模型

> 本文说明这个管理器在「改动用户机器」这件事上设了哪些闸门，以及每道闸门对应哪种具体失败方式。

## 1. 下载与来源

### 主机白名单
只有以下主机会被联系：`github.com` · `codeload.github.com` · `raw.githubusercontent.com` · `api.github.com` · `objects.githubusercontent.com` · `cdn.jsdelivr.net` · `gh-proxy.com` · `ghfast.top`。

要求 HTTPS，且（未走代理时）解析出的地址必须全部是公网地址——用于防止被导向内网。

`objects.githubusercontent.com` 是 GitHub Release 资产下载的重定向目标，在引入 Release Asset 分发后按**实际需要**加入。

### 逐跳校验重定向
只校验交给我们的那个 URL 等于让重定向决定字节来自哪里。因此重定向**手工跟随**（上限 5 跳），**每一跳都重新过一遍主机策略**。跳出白名单即中止。

### 摘要校验
Release 资产若公布了 `digest`，**在解包之前**校验。三种结果严格区分：

| 状态 | 含义 | 是否可安装 |
|---|---|---|
| `Verified` | 字节与发布值一致 | 是 |
| `Mismatch` | **不一致** | **否**，字节被丢弃 |
| `Unavailable` | 上游未公布摘要 | 是，但**按未验证处理**，绝不显示为已验证 |

`Unavailable` 与 `Verified` 的区分是刻意的：git 树分发的上游根本没有发布摘要，把「没有摘要」当成「校验通过」会凭空制造一个不存在的保证。

### 解包不能写出目标目录
压缩包条目自带相对路径，`..\..\x` 会被写到它指向的位置。所有条目**先解析为完整路径并逐个校验**是否落在目标目录内，**全部通过后才开始写**——被拒绝的压缩包不留残留。

## 2. 部署

### 签名先验完整性，再看证书
`X509Certificate.CreateFromSignedFile` 只**提取**证书，**不校验签名是否仍覆盖文件**。篡改过的文件照样能取出证书，因此判定入口统一为 `DeploymentService.ProbeSignature`：`Intact` / `NotSigned` / `BadDigest` / `Unknown`。**`BadDigest` 在任何来源都被拒绝。**

### 事务与回滚
部署是事务性的：覆盖任何文件**之前**先写快照；任何一步失败即回滚，不留半成品、不建立部署记录，且回滚结果**逐条报告**。

### 备份还原前校验 SHA-256
备份记录里的哈希与实际文件不符、或记录缺少哈希，一律**拒绝还原**并保留现场。备份记录中的文件名不得逃出渲染目录。

### 归属不明的文件永不覆盖
热路径入口（`version` / `winmm` / `dinput8` / `dbghelp` / `dxgi` / `d3d12` / `winhttp`）上已有文件时：
- 能确认是**本工具**部署的 → 可处理
- 能识别为**已知兼容 Mod** → 可处理
- **归属不明** → **不算空闲、永不覆盖**。「先备份再覆盖」同样禁止。

## 3. NVIDIA Profile

- **三态必须区分**：`Absent` / `ExplicitValue` / `InheritedDefault`。恢复 `Absent` **必须用删除**；用 `SetSetting(id, 0)` 会把「未设置」永久污染成「显式为 0」，不可逆。
- **撤销能力必须与写入能力同时存在**：若驱动适配器不具备删除能力，则**拒绝写入**（`CanWrite` 要求 `CanDelete`）。一个能 set 但不能 delete 的会话，正是把临时改动变成永久改动的成因。
- **原值必须在任何写入之前记录**：边写边读会让第二次读到自己写的值，回滚于是变成「把我们的值当用户原值写回去」的空操作——表面成功、实际丢数据。
- **原值状态未知时不动作**，而不是猜一个值去覆盖没读到的东西。
- **禁止**改写 `nvdrsdb*.bin`、注册表、DriverStore 或驱动文件；备份使用官方 `NvAPI_DRS_SaveSettingsToFile`。
- **权限运行时探测**，不写死「需要管理员」：官方文档未声明该要求。已提权仍失败报 `Unknown`，不归因为权限。

## 4. 编排顺序

顺序本身就是安全属性：

1. **计划未放行之前不写任何东西**（`Blocked` / `NeedsConfirmation` 路径下不下载、不写文件、不开 DRS 会话）；
2. **先文件后驱动**——失败时不可能留下「Profile 已为某游戏启用，但其代理从未装成」；
3. **回滚先驱动后文件**——用户更可能先发现的反常状态是驱动已开而代理不在；
4. 失败保留**真实错误**，不吞掉换取「看起来成功」。

## 5. 不做什么

- 不引入插件加载器、动态代码执行或远程程序集加载；**远程 JSON 不执行代码**；
- 不修改真实游戏目录以外的系统位置；
- 不打包、镜像或转发任何上游二进制；GPL-3.0 项目代码不复制；专有/EULA 项目不重分发、不改品牌重打包；
- 不在自动测试中触碰真实 NVIDIA Profile（全部用 fake 驱动适配器）。

## 6. 当前未验证的部分（诚实声明）

以下安全机制**已实现并有测试，但未在真实硬件上端到端验证**：

- 真实 NVAPI/DRS 读写——驱动适配器目前是 **fail-closed 桩**（缺官方头文件确认函数 ID 与结构体布局，故拒绝一切写入）；
- 真实 Release Asset 的下载链路（HTTP + 重定向 + 解包）；
- 真实游戏上的部署与回滚。

**自动化测试通过不等于实机验证通过。** 详见各阶段的 `docs/progress/STAGE_NN.md`。
